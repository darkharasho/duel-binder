# Sets Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Sets page listing every set with its art and completion progress, a per-set checklist (owned in colour, missing greyed), and a bulk mode with a `− count +` stepper per card per rarity.

**Architecture:** Set metadata comes from YGOPRODeck's `cardsets.php` during the existing sync and lands in a new `sets` table (schema v2). Completion is computed in main from local `card_printings` and `collection_entries` by a new `repo/sets.ts`, exposed through a new `sets` IPC namespace. Set art goes through the existing image cache and `ygo-img://` protocol under a `set/` path. The renderer adds a `features/sets/` folder; pure view logic (filter, sort, progress, tiles) lives in `setsView.ts` so it is unit-tested apart from the components.

**Tech Stack:** Electron, React 19 + TypeScript, Tailwind v4 + shadcn/ui, TanStack Query, better-sqlite3, Vitest + Testing Library (existing).

**Spec:** `docs/superpowers/specs/2026-10-23-sets-page-design.md`

## Global Constraints

- Run tests with `npm test` (it already passes `--maxWorkers=2`); a single file is `npm test -- <path>`. Never add a second `--maxWorkers`.
- Every task ends green on `npm test`, `npm run typecheck` and `npm run lint`.
- All data access lives in main behind typed IPC (`src/shared/ipc.ts` `Api` + `INVOKE_CHANNELS`); the renderer has no network access and loads images only through `ygo-img://`.
- Set list URL: `https://db.ygoprodeck.com/api/v7/cardsets.php`. Set images are fetched only from `https://images.ygoprodeck.com/images/sets/<key>.jpg`; any other `set_image` value means no image. `num_of_cards` is never stored or used.
- Schema changes are a new migration `{ version: 2 }` appended to `MIGRATIONS`; never edit `SCHEMA_V1`.
- A set is a distinct `card_printings.set_name`, matched exactly. A card counts toward a set only through a printing whose `set_name` is that set. `missing_from_api` printings count in totals and as owned.
- Count modes: `'cards'` (label "Each card once", default) and `'rarities'` (label "Every rarity").
- localStorage keys: `sets.view` (`'grid'` | `'list'`, default `'grid'`) and `sets.countMode` (`'cards'` | `'rarities'`, default `'cards'`).
- Bulk changes record the value snapshot like every other collection mutation (`snapshotAfter` in handlers).
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Rapid clicking in bulk mode**, including `+` on one rarity row and `−` on another row of the same card: the final count equals the clicks, nothing is dropped or doubled, and a `−` that arrives when nothing is left is a no-op, not an error toast. Main no-op pinned in Task 4; renderer queue and cache handling pinned in Task 8.
2. **A checklist refetch racing a bulk click**: a refetch that started before a click finished must not overwrite the newer counts. The bulk path writes the returned card into the cache and does not invalidate the checklist query. Pinned in Task 8.
3. **`cardsets.php` failing or returning junk** (HTTP 500, not an array, rows without `set_name`) while card data succeeds: the sync still reports success and the old `sets` rows survive. Pinned in Task 2.
4. **Odd set codes** (`SDY-E`, `YAP1-EN001`, `DUSA-EN001A`, `PROMO`, no dash): the checklist sorts them sensibly (codes with no number go last), and choosing a default never throws. Pinned in Task 1.
5. **Sets with no metadata, or a `set_image` from another host or with odd characters** (`../x`, a space, `http://`): the set still lists, using a code taken from its printings, with placeholder art; no request leaves for a non-allowed URL. Pinned in Tasks 3 and 4.

# Set Types and Sets Filter Panel Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Classify every set as Booster sets / Decks / Tins / Collections / Promos and move the Sets page's filter and sort controls, plus a new type filter, into a pull-out panel.

**Architecture:** A pure `setType()` in `src/shared/setTypes.ts` classifies from name and code; it is not stored. `setsView.ts` gains type filtering and per-type counts. A new `SetsFilterPanel` (shadcn `Sheet`, controlled by props) holds the controls; `SetsPage` keeps the state, shows the slim bar and the active-filter chips, and persists choices.

**Tech Stack:** TypeScript, React, Tailwind, shadcn/ui (`sheet`, `checkbox`, `toggle-group`), Vitest + Testing Library.

**Spec:** `docs/superpowers/specs/2026-10-25-set-types-design.md`

## Global Constraints

- `src/shared/**` must not value-import electron, better-sqlite3 or node:* (the web worker bundles it).
- Run vitest with `--maxWorkers=2`, e.g. `npx vitest run --maxWorkers=2 <file>`.
- No database migration, no main-process or server change.
- Type labels, in this order everywhere: `Booster sets`, `Decks`, `Tins`, `Collections`, `Promos`.
- Sort labels unchanged: `Newest` (`date`), `Most complete` (`complete`), `Name` (`name`).
- Commit trailer: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. A stale or hand-edited `sets.types` localStorage value (unknown strings, not an array, bad JSON) must be ignored, not crash the page — tested in Task 4.
2. Ticking types that leave no sets must show "No sets match" with the Filters button still usable, not the "You haven't started any sets yet" state unless Progress is Started with no types ticked — tested in Task 4.
3. Search and type filter combine (both must match) — tested in Task 2.
4. "Clear" clears types and progress but leaves sort, count mode and language — tested in Task 4.
5. Title-only core boosters (e.g. `Cosmo Blazer`, `Phantom Nightmare`) never land outside `booster`, even when their names contain words like "Duel", "Force" or "Legend" — tested in Task 1.

# Scan Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A desktop-only Scan page that recognizes cards held up to a webcam, keeps a reviewable session list, and adds it to the collection.

**Architecture:**
- **Pure core** in `src/shared/scan/`: art fingerprints, the fingerprint file format, set-code parsing, rarity choice, name matching and thresholds. The renderer, the main process and the nightly job all use it.
- **Card detection and art matching** run in a renderer Web Worker using OpenCV.js.
- **Text reading (OCR)** runs in the main process with tesseract.js and bundled English data. It's reached over IPC, because Chromium can't `fetch` `file://` language data under the app's CSP.
- **Catalog lookups** run in the main process.
- **Fingerprints:** the nightly catalog job builds a fingerprint file of every `card_images` artwork and uploads it to the portal (R2). The desktop downloads it with an ETag.
- **Renderer orchestration:** a resolver turns raw frame signals into a recognized item, and a showing tracker counts each card once per showing. The session list is persisted in localStorage.

**Tech Stack:** Electron 44, React 19, TypeScript, Tailwind/shadcn, better-sqlite3, vitest. New dependencies:
- `@techstark/opencv-js@4.12.0-release.1` (dependency)
- `tesseract.js@^7` (dependency)
- `@tesseract.js-data/eng@1.0.0` (dependency)
- `jpeg-js@^0.4.4` (dependency; the nightly job and tests decode JPEGs with it)

**Spec:** `docs/superpowers/specs/2026-10-26-scan-design.md`

## Global Constraints

- **Vitest:** run only with `--maxWorkers=2`.
- **Commits:** end every commit message with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Lint:** the repo-wide `npm run lint` already fails on main. Changed files must add no new errors (`npx eslint <files>`). `npm run typecheck` must pass.
- **No network for recognition.** No runtime calls to third-party services, and no CDN paths for OpenCV, tesseract core or language data. The only network use is the fingerprint download from the portal.
- **Desktop only.** No Scan nav item or page on web (`isWeb()`). Web `httpApi` `scan.*` methods reject with `Scan is only in the desktop app`.
- **English printings only:** `card_printings.language = 'en'`. A code whose region isn't `EN` (or absent, as in old `LOB-005` style) counts as unreadable.
- **Nothing reaches the collection until the user presses Add.** Unrecognized cards are never listed.
- **Thresholds in one place:** keep every confidence threshold in `src/shared/scan/thresholds.ts`, because they get retuned on real photos later.
- **Nightly job imports:** code reachable from the nightly job (`scripts/catalog/*`, `src/main/sync/catalog.ts`) must not import `electron`.
- **Desktop migrations are append-only.** This plan adds none; scan data lives in files and localStorage.
- **Copy, verbatim:**
  - Status bar: `Hold a card up`, `Couldn't recognize this card`, and `{name} {setCode} · added, lower it to scan the next card`. When there's no code, it reads `{name} · added, lower it to scan the next card`.
  - Flags: `Check rarity`, `Pick printing`, `From another set`.
  - Footer button: `Add {n} cards to collection` (`Add 1 card to collection` when n = 1).
  - No fingerprints: `Artwork matching is unavailable until the artwork data downloads. Set codes and names still work.`

**Ruling (spec deviation):** the spec says to rank rarities "by the `RARITY_COLORS` order". That object isn't ordered by tier, so this plan adds an explicit `RARITY_TIERS` list (Task 1) that fulfills the spec's intent. If that's wrong, it costs one constant.

## Review Focus

1. **A card tilted or half out of frame for a moment** must not be counted, and it must not be counted twice when it settles. The tracker needs stable frames (Task 7 test `counts once across flicker`).
2. **With a set picked, holding up a card from another set** must give an unsure result or a `From another set` row, never a silent wrong card (Task 7 test `off-set art lookalike is unsure`).
3. **Changing a row's rarity to one that another row already has** merges the two rows and adds their counts (Task 8 test `rarity change merges rows`).
4. **If adding fails partway** (one add rejects), the rows that were added go and the failed rows stay with an error (Task 8 test `partial add keeps failed rows`).
5. **The camera disappearing mid-session** (unplugged, or permission revoked) shows the no-camera message and keeps the list (Task 9 test `camera lost keeps list`).

### Task 1: Shared scan core

**Files:**
- Create: `src/shared/scan/fingerprint.ts`, `src/shared/scan/fingerprintFile.ts`, `src/shared/scan/setCode.ts`, `src/shared/scan/rarity.ts`, `src/shared/scan/names.ts`, `src/shared/scan/thresholds.ts`, `src/shared/scan/types.ts`
- Test: `tests/shared/scan-core.test.ts`

**Interfaces:**
- Produces:
  - `interface RgbaImage { width: number; height: number; data: Uint8ClampedArray | Uint8Array }` in `types.ts`
  - `HASH_WORDS = 8` (256 bits)
  - `artHash(img: RgbaImage): Uint32Array` (length 8). Algorithm: luminance → area-average resize to 32×32 → 2D DCT-II → top-left 16×16 coefficients → each bit = coefficient > median of those 256.
  - `hamming(a: Uint32Array, aOff: number, b: Uint32Array, bOff: number): number`
  - `fingerprintFile.ts`:
    - `encodeFingerprints(entries: { imageId: number; hash: Uint32Array }[]): Uint8Array`
    - `decodeFingerprints(bytes: ArrayBuffer | Uint8Array): FingerprintIndex`. Throws `Error('Not a fingerprint file')` on a bad magic or truncated data.
    - `class FingerprintIndex { readonly count: number; nearest(hash: Uint32Array, k: number, candidates?: ReadonlySet<number>): { imageId: number; distance: number }[] }`
    - Format v1, little-endian: ASCII `DBFP`, u8 version `1`, u16 bits `256`, u32 count, then per record u32 imageId + 32 hash bytes. Records sorted by imageId.
  - `setCode.ts`:
    - `parseSetCode(text: string): string | null` normalizes OCR text to `PREFIX-ENnnn` style:
      - Find a token matching `/([A-Z0-9]{2,5})\s*[-–]\s*([A-Z]{2})?\s*([A-Z0-9]{2,4})/` after uppercasing.
      - In the number part, map `O→0, I→1, L→1, S→5, B→8, Z→2`. The exception is a single leading letter that real codes use (e.g. `DUPO-ENA01` style is rare; keep a leading letter only when the remaining 2–3 chars are digits after mapping).
      - Return null when the region isn't `EN`. Return `PREFIX-number` when there's no region (the caller retries with `EN` inserted).
    - `setCodeCandidates(text: string): string[]` returns `parseSetCode(text)` first, then the same code with every `0` in the prefix read as `O`. It's empty when nothing parses. Callers try them in order.
    - `setPrefix(code: string): string` returns the part before `-`.
  - `rarity.ts`:
    - `RARITY_TIERS: readonly string[] = ['Common','Short Print','Super Short Print','Rare','Super Rare','Ultra Rare','Ultimate Rare','Secret Rare','Ghost Rare','Gold Rare','Prismatic Secret Rare','Starlight Rare','Quarter Century Secret Rare']`
    - `rarityRank(r: string): number`. A variant `"Ultra Rare (Extended Art)"` ranks just after its base. Unknown rarities rank after all known ones.
    - `pickRarity(available: string[], preferred: string | null): { rarity: string; certain: boolean }`:
      - one distinct rarity → it, certain;
      - `preferred` in `available` → preferred, certain;
      - else the lowest rank, not certain.
  - `names.ts`:
    - `normalizeName(s: string): string` lowercases and keeps `[a-z0-9]` only.
    - `bestNameMatch(text: string, names: { id: number; name: string }[]): { id: number; score: number } | null` scores `1 - levenshtein/maxLen` on normalized strings. It returns the best only when `score >= NAME_MIN_SCORE` and `best - second >= NAME_MIN_MARGIN`.
  - `thresholds.ts`:
    - `ART_MAX_DISTANCE = 72`
    - `ART_MAX_DISTANCE_IN_SET = 60`
    - `ART_MIN_MARGIN = 10` (second-best minus best)
    - `NAME_MIN_SCORE = 0.8`
    - `NAME_MIN_MARGIN = 0.05`
    - `STABLE_FRAMES = 2`
    - `ABSENT_MS = 600`
    - All distances are out of 256 bits.

### Task 7: Recognition engine, resolver and showing tracker

**Files:**
- Create: `src/renderer/src/features/scan/vision/vision.worker.ts`, `src/renderer/src/features/scan/engine.ts`, `src/renderer/src/features/scan/resolve.ts`, `src/renderer/src/features/scan/tracker.ts`
- Test: `tests/renderer/scan-resolve.test.ts`, `tests/renderer/scan-tracker.test.ts`

**Interfaces:**
- Consumes: Tasks 1, 2, 6a and 6b.
- Produces:
  - **Worker protocol** (`vision.worker.ts`), with OpenCV loaded inside the worker:
    - in: `{ type: 'init', fingerprints: ArrayBuffer | null }` and `{ type: 'frame', id, image: RgbaImage, candidates: number[] | null, wantBands: boolean }`
    - out: `{ type: 'result', id, signals: FrameSignals }`
  - `interface FrameSignals { found: boolean; art: { imageId: number; distance: number }[]; codeBands: OcrBand[]; nameBand: OcrBand | null }`
  - `createScanEngine(deps: { api: Api['scan']; makeWorker: () => Worker }): ScanEngine`, where:
    - `ScanEngine = { init(fp: ArrayBuffer | null): Promise<void>; analyze(frame: ImageData, opts: { candidates: number[] | null; wantText: boolean }): Promise<RawSignals>; dispose(): void }`
    - `RawSignals = { found: boolean; art: …; codeTexts: string[]; nameText: string | null }`. OCR is called via `api.ocr` only when `wantText`.
  - `resolveSignals(raw: RawSignals, ctx: { setName: string | null; setPrintings: ScanPrinting[] | null; defaultRarity: string | null; lookups: Pick<Api['scan'], 'printingsByCode' | 'printingsForCards' | 'matchName'> }): Promise<ScanOutcome>` in `resolve.ts`.
    - `type ScanOutcome = { kind: 'none' } | { kind: 'unsure' } | { kind: 'recognized'; item: ScanDraft }`
    - `interface ScanDraft { cardId: number; name: string; imageId: number; printingId: number | null; setCode: string | null; rarity: string | null; options: ScanPrinting[]; flag: 'check-rarity' | 'pick-printing' | 'other-set' | null; via: 'code' | 'art' | 'name' }`
    - **Not found:** `found === false` gives `none`.
    - **Code:** take the first of `setCodeCandidates` over `codeTexts` that `printingsByCode` resolves (also try with `EN` inserted for region-less codes). Then:
      - with a set picked and a different prefix → `flag 'other-set'`;
      - rarity via `pickRarity(rarities of that code, defaultRarity)`; uncertain → `'check-rarity'`;
      - `imageId` is the art top-1 if it's among that card's `imageIds`, else `imageIds[0]`.
    - **Art:** top-1 distance ≤ `ART_MAX_DISTANCE_IN_SET` with a set picked (candidates restricted to the set), or ≤ `ART_MAX_DISTANCE` without, and margin ≥ `ART_MIN_MARGIN`. Then:
      - with a set picked → printings of that card in the set → `pickRarity` → flag as above;
      - without a set → `printingId null`, `flag 'pick-printing'`, `options = printingsForCards([cardId])`.
    - **Name:** `matchName(nameText)`. With a set picked and that card in the set, it's handled like an art match within the set. Otherwise `pick-printing`; `imageId` is the card's first image.
    - **Fallback:** otherwise `unsure`.
  - `createShowingTracker(opts?: { stableFrames?: number; absentMs?: number }): { push(now: number, outcome: ScanOutcome): ScanDraft | null; reset(): void }` in `tracker.ts`.
    - It returns a draft once, when the same identity (`cardId:imageId:printingId`) has been recognized in `stableFrames` consecutive pushes.
    - It then returns nothing until `none` has been seen continuously for `absentMs`, or a *different* identity has been stable.
    - `unsure` neither counts nor resets.

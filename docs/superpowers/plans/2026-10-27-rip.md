# Rip Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A desktop-only Rip page where the owner opens simulated booster packs card by card, with holo on Secret/Starlight Rares and a saved history of best pulls.

**Architecture:** Pack layouts and rolling are pure, seedable code in `src/shared/rip/`. The main process owns the pool query, the rolling and the saving (a new SQLite migration, desktop-only), exposed over new `rip:*` IPC channels that the web and phone builds stub out. The renderer gets a `features/rip/` page with a pure opener state machine driving the flip UI, and a `HoloCard` built on the existing `TiltCard`.

**Tech Stack:** Electron, React + TypeScript, Tailwind, better-sqlite3, vitest.

**Spec:** `docs/superpowers/specs/2026-10-27-rip-design.md`

## Global Constraints

- No prices anywhere in Rip: no price fields in Rip types, no price columns in Rip tables, no price text in Rip UI.
- Desktop only: hidden on the web build (`isWeb()`) and absent from the phone shell. Web and phone `Api` objects stub `rip` like `scanWindow`.
- Rip never writes collection entries, value snapshots, sync state, or anything friends can see. Rip tables are never part of sync and are skipped on the server (`server: false`).
- English sets only (`language = 'en'`), visible printings only (`contributed = 0`).
- A set is offered only if it has a researched layout and its local card list can fill every slot.
- Each pack rolled independently; no box guarantees.
- Pulls store a snapshot, not a foreign key to `card_printings`.
- Rip shows the standard card image (`CardArt` with `imageId`, no `printingId`), never `printing_art`.
- Holo: Secret family → diagonal-line holo in the art box only; Starlight and Overframe → whole card; nothing else gets holo. `prefers-reduced-motion` → static shine, no motion.
- Pack count: 1–100 (quick picks 1 / 5 / 24).
- Run vitest with `--maxWorkers=2`.

## Review Focus

1. **Leaving mid-session** (navigating away after 2 of 5 packs): the 2 packs are in History, the session shows "2 packs", nothing crashes on return. → Task 3 test `session counts only opened packs`; Task 6 test `unmount mid-session keeps opened packs`.
2. **A set missing a rarity its layout expects** (an older set in a Starlight-era layout, or a Secret slot in a set with no Secrets): the missing rarity's weight falls to the slot's base rarity; never throws, never returns a short pack. → Task 2 test `missing rarity folds into base`.
3. **Catalog sync deleting a pulled printing**: History still shows the card by name and rarity. → Task 3 test `pull survives printing deletion`.
4. **Fast input** (Space held down, Skip then Next double-clicked): exactly one `openPack` per pack, never past the planned count. → Task 6 tests `next pack only once while loading`, `never opens past packCount`.
5. **Out-of-range counts** (0, 101, 2.5, typed text): the UI clamps to 1–100 and main rejects anything else. → Task 3 test `rejects bad pack counts`; Task 7 test `stepper clamps`.

`RIP_TIERS`, lowest to highest — the spec's order, with Platinum Secret just under Quarter Century Secret and Collector's beside Ultimate:

```ts

  'Common', 'Short Print', 'Super Short Print',
  'Rare',
  'Super Rare', 'Starfoil Rare', 'Shatterfoil Rare', 'Mosaic Rare',
  'Duel Terminal Parallel Rare', 'Ultra Parallel Rare',

  'Ghost Rare',

] as const
```

Lookup strips a trailing `(…)` variant first (so `Rare (Green)` → Rare, `Ultra Rare (Pharaoh's Rare)` → Ultra Rare, `Starlight Rare (Overframe)` → Starlight). Unknown → just above Common (rank between Common and Short Print, e.g. 0.5).

`revealTier`: below Rare → `none`; Rare → `rare`; Super through Ultra family (`Super Rare` … `Premium Gold Rare`) → `big`; `Secret Rare` and above → `huge`.

`holoKind(rarity, variant)`: base contains `Starlight` → `full`; base contains `Secret` → `full` if `variant`/rarity text mentions `Overframe`, else `art`; anything else → `none`.

`artBox`: standard `{ left: 11.9, top: 18.1, right: 11.9, bottom: 29.6 }`. Frame types containing `pendulum` get their own box: measure it from a cached Pendulum image in `~/.config/duel-binder/images/full/` (421×614) in Task 9 and pin the value then; until then use `{ left: 6.6, top: 17.6, right: 6.6, bottom: 25.0 }` (approximate, to be corrected).

### Task 2: Pack layouts and rolling

**Files:**
- Create: `src/shared/rip/layouts.ts`, `src/shared/rip/roll.ts`

- Test: `tests/main/rip-roll.test.ts`

**Interfaces:**
- Produces (in `types.ts`):
  ```ts
  export interface SlotPick { rarity: string; weight: number }
  /** `picks[0]` is the base rarity: it must exist in the set and absorbs missing rarities' weight. */
  export interface PackSlot { count: number; picks: SlotPick[] }
  export interface PackLayout { id: string; label: string; slots: PackSlot[]; source: string }
  export interface PoolCard {
    pkey: string; cardId: number; name: string; setCode: string; rarity: string
    variant: string | null; frameType: string; imageId: number | null
  }
  export interface RipCard extends PoolCard { slot: number }
  ```
- Produces (in `layouts.ts`): `layoutFor(setCode: string): PackLayout | null`, `RIP_LAYOUTS: Record<string, PackLayout>`, `RIP_SET_LAYOUTS: Record<string, string>` (set code → layout id).
- Produces (in `roll.ts`): `mulberry32(seed: number): () => number`, `canFill(layout: PackLayout, pool: PoolCard[]): boolean`, `rollPack(layout: PackLayout, pool: PoolCard[], rand: () => number): RipCard[]`.

**Research (the main work of this task).** Look up real pack layouts and pull rates for TCG English booster sets by era, and encode one `PackLayout` per era with `source` naming where the numbers came from (Yugipedia set pages' "Breakdown"/"Pack contents", Konami product pages). Start with the core booster sets of each era, from *Legend of Blue Eyes White Dragon* through the newest set in the local catalog, plus well-known special packs only where their contents are clearly documented. Map each set by its set code in `RIP_SET_LAYOUTS`. Leave out anything you can't source (Speed Duel, Duel Terminal, Battle Packs, box sets, Deluxe/Super/Advance Editions unless clearly documented). Per-set overrides are separate layouts.

Things to check per era: cards per pack, the common slots (and Short Print / Super Short Print share where documented), whether there is a guaranteed Rare plus a separate foil slot (modern sets) or a single rare-or-better slot (older sets), and the odds of each foil (Super / Ultra / Secret / Ultimate / Ghost / Starlight / Quarter Century Secret / Platinum Secret).

**Rolling rules.**
- Within a slot, choose a rarity by weight. A pick whose rarity has no cards in the pool gives its weight to `picks[0]`.
- Within a rarity, choose a **card** uniformly (by `cardId`), then one of that card's printings at that rarity uniformly (alternate art, Overframe).
- Within a pack, don't repeat a card in the same slot group when the rarity has enough cards; allow repeats otherwise.
- Output is ordered by slot order in the layout (layouts list slots low → high), so the rarest slot is last. `slot` is the card's index in the pack.
- `canFill` is true when every slot's `picks[0]` rarity has at least one card.

  - `ripSession(db, id): RipSessionDetail | null`
  - `ripHistory(db, opts?: { bestLimit?: number; sessionLimit?: number; sessionOffset?: number }): RipHistory` — defaults 12 best, 50 sessions; best pulls sorted by `compareRarity`, then newest first; only cards with `revealTier !== 'none'`.

**Schema** (`SCHEMA_V16`):
```sql
CREATE TABLE rip_sessions (id INTEGER PRIMARY KEY, set_name TEXT NOT NULL, set_code TEXT NOT NULL,
  pack_count INTEGER NOT NULL, started_at TEXT NOT NULL);
CREATE TABLE rip_pulls (session_id INTEGER NOT NULL REFERENCES rip_sessions(id) ON DELETE CASCADE,
  pack INTEGER NOT NULL, slot INTEGER NOT NULL, pkey TEXT NOT NULL, card_id INTEGER NOT NULL,
  name TEXT NOT NULL, set_code TEXT NOT NULL, rarity TEXT NOT NULL, variant TEXT, frame_type TEXT NOT NULL,
  image_id INTEGER, PRIMARY KEY (session_id, pack, slot));
CREATE INDEX ix_rip_pulls_rarity ON rip_pulls(rarity);
```
No foreign key to `card_printings` or `cards`. `ripPool` picks each card's first image (`card_images` lowest `sort_order`).

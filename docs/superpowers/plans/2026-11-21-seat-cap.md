# Seat Cap Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cap new portal accounts at an admin-set number, with a waitlist and one-time invite
links, changeable from the admin dashboard without a release.

**Architecture:**
- A new `workers/portal/src/seats.ts` owns the cap, the waitlist and the invites.
- `createAccount` (signIns.ts), the one place accounts are made, asks it for a seat inside its
  transaction and throws `SeatsFull` when there is none.
- Each sign-in route turns `SeatsFull` into its own error shape.
- Public pages (`/invite/<token>`, `/full`, `POST /waitlist`, site `/waitlist`) and an admin
  Seats tab (web and desktop) sit on top.

**Tech Stack:**
- Cloudflare Worker and Durable Object SQLite (better-sqlite3 in tests).
- TypeScript and vitest.
- React for the desktop admin.

**Spec:** docs/superpowers/specs/2026-11-21-seat-cap-design.md

## Global Constraints

- **Migration:** a new step `server-51` in `SERVER_STEPS` (workers/portal/src/migrate.ts). The cap
  defaults to 100.
- **Seats used:** `COUNT(users WHERE closed_at IS NULL)` + invites with `used_at IS NULL AND
  expires_at > now`.
- **Invites:**
  - The raw token comes from `randomToken()`; only `sha256Hex(token)` is stored.
  - An invite lives 14 days.
  - The link is `${PUBLIC_URL}/invite/<token>`.
- **Cookie:** `seat_invite`, made with `cookie()` from auth.ts (HttpOnly, Secure, SameSite=Lax),
  path `/`, max-age equal to the invite's remaining life.
- **Waitlist IP limit:** `takeLimit(db, 'waitlist-ip', ip, now)`. Add the kind with a 5-a-day
  window, wherever authLimits.ts defines `beta-ip`.
- **Error codes:**
  - desktop and native callback: `error=full`
  - Apple JSON: `{ error: 'full' }` with status 403
  - email: `EmailAuthError(EMAIL_COPY.full, 403)`
  - web: a 302 to `/full`
- **Existing accounts:** signing in to an account that already exists never reaches the seat check.
- **Admin routes:**
  - Use `isAdmin` (404 otherwise), plus `adminWriteAllowed` and `isJson` on writes, as beta.ts does.
  - Tests use the vitest maxWorkers ≤ 2.
- **Copy:** "Duel Binder is full for now", "Join the waitlist", "A seat opened up".

## Review Focus

- **An invite used twice.** Two sign-ins carrying the same cookie at once: only the first makes an
  account, and the second gets `SeatsFull` when the cap is full.
- **An expired invite.** The cookie is still set but the invite is past `expires_at`: refused at the
  cap like anyone else, and `/invite/<token>` shows the expired page.
- **A returning user while full.** An existing Discord, Apple or email user signs in with the cap
  at 0: it succeeds.
- **The cap lowered below the accounts in use.** No one is removed, `free` shows 0 (never
  negative), and `fill` invites no one.
- **A failed invite email.** The invite row is gone afterwards, the entry stays uninvited, and
  fill moves on to the next entry.

### Task 1: Seats core (data, counts, waitlist, invites)

**Files:**

**Interfaces (Produces):**
```ts
export class SeatsFull extends Error {}
export interface SeatCounts { cap: number; accounts: number; invited: number; free: number; waiting: number }
export interface SeatPass { inviteHash?: string | null; verifiedEmail?: string | null }
export function seatCounts(db: SqlDb, nowIso: string): SeatCounts
export function setCap(db: SqlDb, cap: number, nowIso: string): void          // integer ≥ 0
/** Inside createAccount's transaction: the invite to spend (its hash), or null when a free seat is
 * used; throws SeatsFull when neither. Invite first (by hash, else by verifiedEmail). */
export function takeSeat(db: SqlDb, pass: SeatPass, nowIso: string): string | null
export function spendInvite(db: SqlDb, inviteHash: string, userId: number, nowIso: string): void
export function inviteValid(db: SqlDb, inviteHash: string, nowIso: string): { expiresAt: string } | null
export function joinWaitlist(db: SqlDb, email: string, nowIso: string): void   // INSERT OR IGNORE
export async function inviteEntry(deps: AppDeps, waitlistId: number): Promise<boolean> // ignores cap
export async function fillSeats(deps: AppDeps): Promise<number>                // invites sent
export async function resendInvite(deps: AppDeps, waitlistId: number): Promise<boolean>
export function cancelInvite(db: SqlDb, waitlistId: number): boolean
export function deleteEntry(db: SqlDb, waitlistId: number): boolean
export function seatInviteMessage(email: string, link: string, expiresAt: string): EmailMessage
```

**Tables (server-51):**
- `seat_settings(id INTEGER PRIMARY KEY CHECK (id = 1), cap INTEGER NOT NULL, updated_at TEXT NOT
  NULL)`, seeded with `(1, 100, <migration time>)`.
- `waitlist(id INTEGER PRIMARY KEY, email TEXT NOT NULL UNIQUE, created_at TEXT NOT NULL,
  invited_at TEXT)`.
- `seat_invites(token_hash TEXT PRIMARY KEY, waitlist_id INTEGER, email TEXT NOT NULL, created_at
  TEXT NOT NULL, expires_at TEXT NOT NULL, used_at TEXT, used_by INTEGER)`.

**Behaviour:**
- **`inviteEntry`:**
  1. Writes the invite row and sets `waitlist.invited_at`, voiding any earlier unused invite for
     that entry.
  2. Sends `seatInviteMessage` through `deps.email`.
  3. On a send failure or no sender, deletes the row, clears `invited_at`, and returns false.
- **`fillSeats`:**
  - Loops over entries with `invited_at IS NULL`, ordered by `created_at, id`, while `free > 0`.
  - A failed entry is skipped for this run.
  - Expired, unused invites free their seat: `fillSeats` first clears `invited_at` on entries whose
    newest invite expired unused, then puts them at the back. (My call: an expired invite gives
    someone else a turn.)
- **`cancelInvite`:** deletes the entry's unused invites and clears `invited_at`.
- **`seatInviteMessage`:** uses `brandedHtml` / `para` / `small` / `escapeHtml` from emailSend.ts,
  like `betaAddedMessage`. Subject: "A seat opened up at Duel Binder". It includes the link and
  the expiry date.

### Task 2: The gate in account creation, and every sign-in route's answer

**Files:**
- Modify:
  - `workers/portal/src/signIns.ts`: `createAccount` and `signInWith` take an optional
    `pass: SeatPass`.
  - `workers/portal/src/auth.ts`: `discordSignIn`, the web callback, the desktop/native callback,
    `exchangeAppleToken`.
  - `workers/portal/src/emailAuth.ts`: the `create` pre-check, and `createFromFlow` plus the
    `claim-separate` step taking a pass.
  - `workers/portal/src/emailPages.ts`: the form route passes the cookie's invite.
  - `src/shared/emailAuth.ts`: `EMAIL_COPY.full`.
  - Account-close paths: merge.ts (the close at :377) and the delete-account route. Find them by
    `closed_at` / `DELETE FROM users`.
- Test: `tests/portal/seat-gate.test.ts`

**Interfaces:**
- **Consumes:** Task 1 `takeSeat`, `spendInvite`, `SeatsFull`, `fillSeats`.
- **Produces:**
  - `createAccount(db, id, profile, nowIso, pass?: SeatPass)` calls `takeSeat` before the insert
    and `spendInvite` after it.
  - `signInWith(db, id, profile, nowIso, pass?: SeatPass)` passes the pass through only on first
    use.
  - `readSeatInvite(req): string | null` in seats.ts reads the raw token from the `seat_invite`
    cookie. Callers hash it with `sha256Hex` before the transaction.

**Behaviour:**
- **Web Discord callback:** passes `{ inviteHash }` from the cookie. On `SeatsFull`, a 302 to
  `/full` (the same for the `scan` next), clearing `oauth_state`.
- **Desktop and native callback:** passes no invite. On `SeatsFull`,
  `desktopCallback(desktop, { error: 'full' })`, following how `signin-failed` is built.
- **Apple:** passes `{ verifiedEmail: email }`. On `SeatsFull`, 403 `{ error: 'full' }`.
- **Email `create` step:** throws `EmailAuthError(EMAIL_COPY.full, 403)` when `seatCounts(...).free
  === 0` and the body or caller carries no valid invite. Only new sign-ups reach this step;
  `hasEmailSignIn` already rejects known addresses.
- **Email `confirm` / `separate` / `claim-separate`:** the web form route passes the cookie's
  invite hash. On `SeatsFull`, `EmailAuthError(EMAIL_COPY.full, 403)`.
- **Successful creation with an invite:** the web routes clear the `seat_invite` cookie.
- **After an account closes:** `await fillSeats(deps)` runs after the transaction commits.
  Failures are logged and never fail the close.
- **`EMAIL_COPY.full`:** "Duel Binder is full for now. Join the waitlist at duelbinder.com/waitlist
  and we'll email you when a seat opens."

### Task 4: Admin Seats routes and the web admin tab

**Files:**
- Modify: `workers/portal/src/seats.ts` (add `adminSeatsRoute`), `workers/portal/src/app.ts`,
  `workers/portal/src/adminPage.ts`, `src/shared/admin.ts` (types)
- Test: `tests/portal/seats-admin.test.ts`

**Interfaces:**
- **Produces these routes:**
  - **`GET /admin/seats`** returns `AdminSeats` = `{ counts: SeatCounts, waitlist: AdminWaitlistEntry[] }`.
    - `AdminWaitlistEntry` is `{ id, email, createdAt, invitedAt, inviteExpiresAt, status:
      'waiting' | 'invited' | 'expired' | 'joined' }`.
    - Entries are ordered by waiting first (by `createdAt`), then invited, then joined.
    - It is read-only: it never sends anything.
  - **`POST /admin/seats/cap {cap}`:** an integer from 0 to 100000, else 400. It runs `setCap`
    then `fillSeats` and returns `{ ok, invited }`.
  - **`POST /admin/seats/fill`** returns `{ ok, invited }`.
  - **`POST /admin/seats/invite {id}`, `/resend {id}`, `/cancel {id}`, `/delete {id}`:**
    - They return `{ ok: true }`, and `invite` and `resend` add `emailed`.
    - An unknown id gets 404, and a failed send gets 502 `{ error: 'email' }`.
- **Web tab (adminPage.ts):** a "Seats" tab, wired like `loadBeta` (TABS, nav, section, refresh).
  - **The top:** a cap number input with Save, a "Fill open seats" button, and the line "used N
    of CAP · invited N · free N · waiting N".
  - **The list:** the entries, each with its buttons by status: waiting gets Invite now and
    Delete, invited gets Resend and Cancel, expired gets Invite now and Delete.
